## 分开报告的验证层级

| 层级 | 必需证据 | 可以得出的结论 |
|---|---|---|
| 备份与恢复 | 归档及清单摘要、实际隔离恢复、路径/类型/模式/字节比较 | 该归档能恢复记录范围内的内容，包含隐藏和未提交文件 |
| 来源与静态检查 | 来源锁、完整包核验、构建一致性、语法与治理检查的命令及退出码 | 直接来源完整、自有构建物与源码一致、受控链接转换正确、结构性规则满足 |
| 行为回归 | 完整候选 SHA、实际测试代码、命令、数量、失败及跳过明细 | 已执行的治理、写入保护、CI 和运行时场景符合断言 |
| 会话选择与恢复 | 状态接口退出码、私有记录、模式/版本/历史及子调用继承证据 | 该根身份的选择已持久化；不代表用户已经批准交付门禁 |
| 项目入口 | 原字节、区块摘要、追加/匹配结果 | 入口文件存在且块匹配；不代表宿主加载 |
| TeamAI 实际分发 | 固定 CLI 版本、隔离成员环境、真实输出与源包比对、安装回执 | 指定 harness 的目标文件已完整生成和安装 |
| 宿主加载 | 实际宿主对 Skill 和原生配置的加载结果 | 该宿主已发现并加载声明的资源 |
| 原生角色调用 | 真实调用、角色身份、权限与调度证据 | 该调用范围内的角色行为符合协议 |
| 外部集成与发布 | 获准目标环境、固定部署版本及真实验收结果 | 仅该外部环境及场景完成验收 |

文件分发成功不证明宿主已经加载，版本探针不证明角色已经调用，静态配置解析也不能代替权限行为验证。每个不可用或未执行的切片单列 `not_run`，说明环境或授权缺口；不能用另一个层级的通过填补。

## 结果与候选的绑定

执行者记录真实 `base_sha`、`head_sha` 或 `tested_sha`，并保存实际命令、退出状态、失败分类及必要输出。没有本次主仓提交时如实标注 HEAD 仍为基线；仓外隔离 Git 的 SHA 单独标明，不冒充主仓 HEAD 或正式 G5–G10 完成。

测试者与实现者串行修改各自负责的文件；独立审核针对包含生产代码、测试、生成物和必要文档的完整候选。后续修改形成新的身份，旧报告保持原义。只有已运行且符合对应 Oracle 的结果才可标为通过；未运行、失败、阻塞和已登记历史债务分别记录。

运行 `npm run build`、`npm test` 和 `npm run check` 后，仍需核对变更范围、导入包和用户内容保护。远端 CI、分支保护、跨机器宿主运行及发布不因本地检查成功而自动生效。
