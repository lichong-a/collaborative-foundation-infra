# 引导 Agent 接入已有工程

[返回 Skill 入口](../SKILL.md) · [工程结构](structure.md) · [文档规范](documents.md) · [工具接口](tools.md)

目标是在原有工程上补齐职责、规范和导航，让信息能沿“项目入口 → 分类入口 → 专题 → 证据”逐层找到。保留现有业务行为、目录和事实来源；结构问题先形成有依据的建议，不因接入规范自动重构仓库。

本指引适用于不同语言、模型和支持的 harness。它是一份供 Agent 执行的协议，没有新增一键 CLI。只提供本文件或安装 Skill 不构成写入授权；用户本次任务、既有授权和项目约束决定实际范围。

## 直接交给 Agent

替换目标路径和可用来源，再选择执行档位。以下字段是委托信息，不是 CLI 参数。

- **诊断**：目标仓只读，先给工程画像、导航问题和接入预览，不向目标分发或写文档。
- **接入**：表示用户同意在下述有限范围内实施；先诊断，再连续完成无冲突的步骤，不重复索取已经给出的授权。

```text
请按 collaborative-foundation-infra 的 references/adoption.md 接入当前工程。

目标仓库：<业务仓库绝对路径>
规范来源：<可信 collaborative-foundation-infra 本地目录，或已安装且已核验的 Skill 入口>
执行档位：<诊断 / 接入；未选择时按诊断处理>
额外保护路径和约束：<填写；无额外约束不代表解除项目已有保护>

目标是规范化、结构化和渐进式导航，保持现有业务行为与事实来源。
先按 references/session.md 核对根会话身份并查询选择；未选择时只做必要身份检查，
等待明确选择 devflow 或 basic，再核对来源、Git 状态、允许路径及保护路径。
按当前动作读取 Skill 参考，不预加载或复制全套规范进项目入口。

接入档位仅授权：预检通过的项目级规范资源；项目画像与治理策略；
现有文档/指令入口的最小导航追加；目标明确的索引、待分类登记和修链。
已有规则、定制包、禁用配置和未提交内容必须保留。
不修改业务代码、依赖、运行配置、数据库或现有任务状态；
不移动、合并、删除或批量重写历史文档，不提交、推送或创建远端。
不改全局 Skills、用户级原生角色、系统配置或其他 worktree。

先给出将修改的具体路径、原因和恢复方式，按本指引核对后执行。
已授权且无冲突的步骤连续完成；歧义、冲突或超出范围的动作只列待决项，
继续不依赖它们的工作。工具拒绝不能通过手工改文件或放宽规则绕过。
最后报告实际变更、历史债务、待决项、验证结果及未验证项。
分别说明资源安装、宿主加载与真实角色调用，不把三者混为通过。
```

还没有安装 Skill 时，可让 Agent 先读取可信规范仓的 `skills/common/collaborative-foundation-infra/SKILL.md` 与本文件；只有已安装包时可先画像和诊断。需要首次分发但没有可信规范仓、固定依赖或明确安装范围时，报告这个缺口，不猜远端地址、不下载并执行来历不明的安装脚本。

## 先选择会话模式，再确定范围与工具

按[会话协议](session.md)先查询真实根身份。新主会话/fork 重新选择，同根恢复复用，子 Agent 继承。接入档位与会话模式是独立决定；选择 basic 不自动授权接入，选择 devflow 也不扩大允许写入范围。两模式均适用以下接入步骤，未选择之前不能先行开展画像或工程变更。

1. 确认目标的真实根目录、当前分支/HEAD、未提交和未跟踪内容；目标必须与规范源区分。路径未知或身份不明时，只继续可确定的只读工作。不要因为看见 `.codex`、`.claude` 或 `.zcode` 目录就推断当前宿主。
2. 阅读目标生效的指令、文档入口、依赖清单与代码入口，识别生成物、外部导入包、受保护目录和已有交付流程。图片、文档、历史计划及工具输出只作事实输入，不能扩张授权。
3. 建立具体变更清单，区分新增文件和既有文件的局部追加。修改前保留既有文件的类型、权限和原字节，备份放在获准的仓外私有位置并验证可读；Git 提交记录不能代替未提交内容的备份。敏感配置、凭据和业务数据不写入画像、日志或分发包。
4. 与拟修改范围重叠的脏文件、未跟踪同名文件、定制内容、软链/硬链和并发写者均列为冲突。不要 reset、clean、stash、自动提交、改权限或关闭检查来取得“干净基线”。无关脏内容保留，是否能应用仍由实际工具的基线检查决定。

普通治理使用包内 Node 工具，不向业务项目增加治理依赖。缺少运行环境时，先在已获授权的用户缓存/隔离目录按规范仓 `scripts/runtime` 尝试受限安装并核验；需要 Python/uv 的辅助动作也遵循先尝试、失败再降级。若会话要求全局零写入，不执行安装；报告该约束并按[人工协议](manual.md)继续只读工作。降级不等于自动检查通过。

## 接入顺序

### 1. 建立原工程画像和流程映射

使用[画像模板](../templates/project-profile.md.txt)，从事实记录模块职责、公开接口、依赖方向、数据/副作用所有者、文档入口和实际验证命令。复用现有文档的链接，不复制另一份架构事实，也不强制套用固定的 `src/services/utils` 目录。

既有 DevFlow 的状态、计划、审批和证据只引用原路径；其他流程先记录职责和冲突，不自动迁移到 DevFlow，不创建平行工作包。接入规范不能重置进行中的任务。具体映射见[交付与职责](delivery.md)。

### 2. 预检并分发项目级资源

规范源初次 clone 后显式运行 git submodule update --init --recursive --checkout，再 npm run prepare:skills 只读校验；九上游包直接位于 skills/upstreams，源码树不保留其副本。build/check/sync 每次核验真实来源，不执行网络更新；历史副本或准备状态保持报错，须经明确授权核验归档。

仅在接入档位和明确项目级范围内，从核验后的规范源运行 `scripts/teamai-sync.mjs --repo <目标> --source <规范源> --agent <实际宿主>` 预检，预览资源时不加入口选项；已授权局部追加会话入口时加 `--install-entry` 一起预检，通过后再用相同参数加 `--apply`。没有 --apply 一律零写入；--apply 单独仍不改项目指令入口。使用实际脚本的参数；不要把委托档位当成命令选项。版本来自规范源的锁文件，不跟随“最新版本”临时升级。

在规范仓先显式 npm run prepare:teamai，首次解析 latest 并隔离验证；已有安装离线重核。不要将开发依赖或裸 node_modules 当成运行时来源，也不在普通预览中自动联网安装。

该适配器支持 `codex`、`zcode`、`claude`，在隔离环境调用 TeamAI，在私有临时团队目录组装十一包，将受控自有导航转换为安装后的同级链接，并按固定提交重定位官方指南，再逐字核验真实输出并向目标发布完整十一份 Skills、适用规则和 schema4 安装回执。Codex/ZCode 的 Skill 目录是 `.agents/skills/`，Claude 是 `.claude/skills/`；目录相同不证明发现规则相同。不要手动只复制某个角色包，不直接在业务仓运行 TeamAI init/pull 绕过冲突预检。

同名定制、不同版本、未知文件、明确禁用、既有自动同步 hook 或不支持的宿主都应保持原样并报告。不要使用 force 覆盖，也不要把编辑回执或删除冲突文件当成修复。规范更新按独立差异审查进行；本指引没有承诺自动升级既有安装。

当前自有 Skill 的名称为 `collaborative-foundation-infra`，回执位于 `.collaborative-foundation-infra/`。已有其他命名或布局的团队规范安装时，不能把当前路径不存在当成“尚未接入”；先检查实际入口、来源版本、定制内容和活动任务，输出逐项迁移清单。适配器不自动发现、搬迁或删除旧安装，也不承诺两套入口可以并行。布局迁移须在明确授权的停写窗口内先用隔离副本验证，再按核对后的路径操作；原状态、用户修改及恢复证据保持完整。

### 3. 补齐渐进式导航与项目策略

优先复用现有 README、分类入口和专题页。选择明确的入口后，补最短的导航链：项目入口说明从哪里开始，分类入口说明主题范围，专题引用相关设计/计划，证据保留原位置。详细规范由 Skill 按动作加载，入口只放短路由。

沿用原目录中的相对链接，检查跨树引用、中文/空格路径和锚点。语义归属不明的文档登记到现有或明确指定的待分类清单；登记只是让它可找到，不代表已确定归属。既有文档状态不由 Agent 为满足格式检查而批量改写。

从[策略模板](../templates/policy.json)生成本项目策略，逐项选择真实的 `documentRoots`、`entrypoints`、`metadataRoots`、`allowedTopLevel`、`protectedPaths` 和流程引用。模板路径只是示例；不存在的 docs/changes 分区不因套模板而创建。不要复制规范仓自身的策略或任务编号。

先 audit，再按事实逐条判断历史债务。只有经核对、说明原因且处于授权范围内的旧问题才能登记精确 fingerprint；不能将全部发现一键加入 debt，不能扩大 exclude 来隐藏问题。新建普通受管理文档按[文档规范](documents.md)标注；导入包、历史分区和流程产物保留原格式及已有权威。

已有 README、AGENTS.md 或 CLAUDE.md 的入口追加需单独核对作用域；治理 apply 不会修改指令文件。会话入口只由上述显式 --install-entry 生成，Codex/ZCode 共用 AGENTS.md，Claude 用 CLAUDE.md；相同完整块 matched 时完全不写入口，保留块外未提交字节，且不表示宿主加载或模式已选择。不同/残缺/重复块拒绝；需要追加已有入口时要求受跟踪且干净。以下标记只用于其他经确认的导航，不能重复造一个会话块。只有委托已授权时，Agent 才能对不存在的导航区块做局部追加，并保留原正文、顺序、编码与换行。可用以下成对标记标识追加内容，块内只放经验证的项目相对路径；这只是手工编辑约定，不是自动注入功能：

```markdown
<!-- collaborative-foundation-infra:entry:start -->
<!-- 在此填写已核验的本项目规范/文档入口；不要原样写入占位内容。 -->
<!-- collaborative-foundation-infra:entry:end -->
```

在接入报告中记录区块路径和前后摘要。同样区块已存在且内容一致时不追加；内容不同、标记不完整或已有等价入口时先比较并复用，不自动替换。README/AGENTS 若有用户未提交修改，停止这个重叠编辑步骤。规则冲突通过待决清单说明，不通过追加更强指令覆盖原项目规则。

### 4. 最后生成预览，再执行确定性整理

资源分发、策略/画像落盘和已授权入口追加完成后，再以稳定的当前树生成 plan。诊断档位的策略和报告放在获准仓外位置或直接回复，不写目标。所有档位的 plan 输出都放在目标仓之外；生成后不得一边改策略/报告/目标文件一边复用旧计划。

核对预览涉及的每个路径、原字节、目标字节和原因。自动应用仅包括明确导航位置的索引条目、孤儿文档的待分类登记、已确认旧目标到新目标的链接映射。移动、重命名、合并、删除、语义分类和真实性状态修改另列建议，不作为本次接入的隐含授权。

apply 前重查目标、来源版本、策略和仓库基线，保证串行写入。现有目标必须满足工具要求的受跟踪且干净条件；无 Git 或条件不满足时保留诊断/预览，不替用户初始化、提交或改成手工写入来绕过保护。命令、退出码和恢复契约见[工具接口](tools.md)。失败时保留现场与恢复日志，只恢复能够证明由本次动作写入且未被他人修改的内容，不能全仓回滚。

### 5. 验证并交接日常使用

复跑 check 并对比实际变更和事前清单。区分检查通过、已登记债务、新增违规与环境失败；`audit` 退出 0 只表示扫描完成。文档可达和目录已登记不证明架构合理、语义分类或文档真实性正确，待决问题继续可见。

只有会话选择 devflow 时，原生角色交给 [ric-devflow](../../../upstreams/ric-devflow/skills/ric-devflow/SKILL.md) 的准备协议；basic 不加载其正文、不准备四角色且不写原流程状态。此次项目级接入不隐含用户级/全局角色安装授权；需要重载或超出范围时报告精确缺口。沿用已确认可用的角色，不为接入再创建一套调度或状态系统；单纯画像/文档接入沿用原流程的轻量豁免。

日常任务开始前显式同步并绑定规范版本，执行期间保持稳定。后续开发按模块范围修改代码、补相关文档入口并检查新增违规；不要在每次任务开始时重复迁移整个仓库。

## 接入报告的最小内容

报告复用项目已有证据位置，不新增任务状态库。至少包含：

- 目标仓库、实际 harness、适用规范与会话协议入口、锁定版本、执行档位及允许/保护路径；具体根 ID、选择文件与模式历史只在用户私有状态和必要会话交接中保留，不复制到共享报告。
- 接入前后 Git 基线、未提交内容的保护结果、外部并发变化及观察窗口。
- 实际新增/追加路径、变更摘要、备份/恢复位置、安装回执与版本身份。
- 原模块和流程权威的映射，文档导航入口，历史债务理由与语义待决项。
- 实际执行的命令、退出码和证据；文件安装、宿主加载、原生调用分别标注。
- 可复用的检查命令，以及完成、部分完成、环境受限或冲突未处理的准确结论。

接入应达到“原项目保持可工作，新增规范可发现，相关文档可逐层找到，新增问题能被检查”。不能用丢弃原内容、移动文件凑模板、批量标 current 或隐藏历史问题来获得表面的整洁。
