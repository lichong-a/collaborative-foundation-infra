# 工具不可用时的人工协议

[返回入口](../SKILL.md) · [会话选择](session.md)

自动工具不可用时先运行规范仓 scripts/runtime，按当前动作尝试用户目录安装 Node，只有辅助动作需要时才准备 Python/uv。禁止 sudo、改系统配置、改 shell profile 或往业务项目加治理依赖。安装失败后保留失败命令、退出码、校验结果和环境范围；CI 返回失败，Markdown 降级不等于自动检查通过。

## 先保全本根会话选择

没有 Node 不表示默认启用 DevFlow，也不表示协议必然无法执行。宿主仍有安全本地文件能力时，可以沿用[会话协议](session.md)的真实项目/宿主/根 ID 身份，持久化可核验人工交接记录后继续；只在口头记住一次选择不满足要求。未选择前仍只做必要身份核对，按原顺序询问两项；恢复旧根时核对记录，新根和 fork 不借用旧选择，子 Agent 只继承。

人工记录与工具记录使用相同的 UTF-8 SHA256 身份算法、规范版本、devflow/basic 含义和完整 select/switch 历史。项目摘要取实际共享 Git common-dir（非 Git 取真实根路径），根会话 ID 单独摘要，宿主明确为 codex/zcode/claude；不记录对话、任务内容或原始 ID。规范版本取已核验工具构建所绑定的 64 位摘要，不能临时编造或以版本号 1.0.0 代替。

使用绝对 XDG_STATE_HOME 或用户 .local/state，人工文件为 collaborative-foundation-infra/sessions/<项目摘要>/<宿主>/<根ID摘要>.manual.json。字段为 schemaVersion:1、recordKind:manual、identity（project/agent/rootSession）、mode、selectedAt、standardVersion、history；history 每项 action/mode/selectedAt/standardVersion，顺序与工具协议相同。人工文件独立于工具 .json，不覆盖它。目录仅用户所有且 0700，记录 0600，拒绝软链/硬链、已有不明文件和并发写者。先排他锁、完整写入同目录私有临时文件、同步、重查旧原字节、原子发布并读回核验；保存操作命令及读回摘要作为交接证据。不能可靠实现这些保护、确定身份/版本或持久化记录时暂停开发，报告具体阻断。

已有工具记录损坏、身份不符、版本漂移或锁未恢复不能用人工文件绕过。工具恢复后检测到 manual 文件会拒绝自动选择；先停止本根活动执行者，核对人工文件与任何已有工具记录的同一身份、版本和完整历史。保留人工原始字节及摘要到用户私有归档，经明确人工接管操作把核验后的字段转换为工具 schema（仅去掉 recordKind），按同等原子发布保护写入 .json，再将 manual 文件移入归档，最后运行 session status 并核对完整历史。不同或不明记录保留并报冲突；不静默覆盖，不以新 select 丢弃人工历史，归档和接管不改变原选择时间。

## 按已选模式继续共同规范

确认任务授权和允许路径，登记目录职责，从项目入口逐层走到新增文档，检查每条改动链接和状态标签，对照调用方审查共享边界并保留真实验证证据。devflow 才按原协议维护原事实源和四角色审核；basic 使用原项目方法继续授权工作，不加载五份交付 Skill 正文、不准备四角色、不写 .devflow，也不另建任务状态库。

旧仓只输出问题清单和最小补索引建议。语义归属不明的文档列待分类，不猜测移动目标；新项目按需求、技术栈和部署提出最小职责树，纳入当前方案确认。没有安全快照、恢复方案和足够权限时暂停写入。自动工具的安全拒绝不能用手工改文件或放宽规则绕过。

环境恢复后重新运行自动检查，再报告实际通过项。工具缺失不会授权跳过已选流程的独立审核或捏造宿主调用。
