# 测试、审核与证据边界

[返回入口](../SKILL.md)

先语法和受影响测试，再按风险执行契约、集成和端到端。测试覆盖用户可见行为、权限、边界输入、失败、取消、重复和并发，不围绕内部调用顺序造无效覆盖。

报告分开：静态文件/配置核验；合成隔离测试；本地真实工具进程；原生 harness 加载与角色调用；外部业务验收。前一层通过不能替代后一层。

每个结果记录命令、工作目录、工具版本、退出码、输入和真实 base/head/tested SHA。无提交时记录不可变本地快照摘要，并注明无法替代要求真实代码 SHA 的正式门禁。未运行、失败、阻塞必须真实落盘。

devflow 模式下，Reviewer 不审核自己的实现，Tester 保持测试 Oracle 独立，发现问题交唯一 Planner 归因；basic 沿用项目已有审核方法，不因此启动四角色。任何模式都不能由实现者改验收要求或降低正确断言来凑通过。

CI 必须从可信目标版本启动检查器并读取该版本策略、依赖锁和构建产物。候选修改治理工具或规则单独审核，不能执行候选自带脚本再相信其成功。远程分支保护需要仓库管理员实际配置，文档不能冒充部署证据。

交接说明已完成、实际受测身份、未运行项、风险、下一角色和保护范围。devflow 模式的流程状态遵从原 DevFlow；basic 只读保留其状态，按用户授权和项目原验收要求交付。任何模式都不以所有工具退出零自动关闭其他流程任务。
