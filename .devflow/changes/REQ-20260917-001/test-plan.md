1. Planner 固定计划并安排独立 `TEST_REVIEW`。
2. 在生产写入前执行仓外基线检查，发布基线结果和失败分类；核验备份及保护范围初始清单。

4. Tester 仅更新 `tests/`，保留原 34 项并增加窄范围断言；交回包含测试代码的完整候选。
5. 在完整 `tested_sha` 上运行构建、全部回归、实际 TeamAI 分发、可信 CI、运行时与分发后导航验证。
6. 对完整候选执行残留扫描、导入包与 `.git` 比对；人工核验文档权限边界和报告语义。
7. 返回测试报告和必要 Defect，由 Planner 安排完整候选独立审核。审核导致代码或测试变化时，只对新身份执行受影响补测及必要回归，不改绑旧报告。

### 失败、未运行与退出条件

- **PASS**：本计划声明的必需本地切片均通过，保护范围未变，候选可恢复，证据足以复现。结果限定为当前平台和声明环境。
- **FAIL**：任一必需 Oracle 或保护性回归失败。创建绑定 `found_on_sha` 的不可变 Defect，包含真实命令、输入、预期、实际、最小复现及疑似分类，交 Planner 归因。
- **BLOCKED**：缺少计划审核、可恢复候选、必要环境或真实边界，无法可靠判断对应必需切片。
- 不可用原生宿主的加载和调用，以及其他操作系统、远端 CI 服务及生产环境，单列 `not_run`。本次改名不改变原生角色定义，因此这些未运行项不替代或否定已经完成的本地文件分发验证，也不允许据此声称原生调用通过。
- 报告不得声称当前仓库正式 Git 门禁完成；外部隔离候选及本地交付结果分别记录。
